Stated plainly: the checks derived from the rules answer "is this a valid instance of the standards it pins?", and neither "are the described data FAIR?" nor "do those data exist and are they any good?".

## The transferable contribution

Three mechanisms, none specific to SOCIB or to the standards loaded today.

- **Deterministic identity.** Deriving every generated entity's identifier from the rules field it came from lets independent generators agree without sharing anything. [Identifiers](../guide/identifiers.md)
- **A single decision point.** What a field becomes is decided in one place every generator asks. [Knowledge model](../guide/knowledge-model.md)
- **Tighten-only profile merging.** A profile may make a field mandatory or narrow a vocabulary, never loosen or reshape; where two profiles disagree the merge says so by name. Adding a national or thematic profile is a data change. [Rules](../guide/rules.md#standards-and-profiles)

Honest scope: on the standards loaded, the merge currently performs no tightening, because the OSTrails profile only adds fields. It is exercised on fixtures, and becomes load-bearing with the first profile that constrains an existing field.

## What has moved on since the deliverable

The deliverable described three repositories: the engine, the DS Wizard deployment, and a git registry the submissions were committed into. They are now **one repository**, and the registry is replaced by a **DMP API and its database**:

| At the deliverable | Now |
|---|---|
| a quality control in the submission webhook | the same assessment, in the API, on every write |
| each submission committed into a git registry | each submission stored as a version of the project's template DMP, with its assessment |
| a generic plan with placeholders, resolved later | a template DMP, and production DMPs filled from its versions, through the same API |
| docker compose, then Kubernetes | Docker Compose and Kubernetes from one set of values, deployed by the GitLab CD |
| three repositories, three CIs | one repository, the same pipeline on GitHub and GitLab |
